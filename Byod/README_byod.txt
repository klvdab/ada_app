안드로이드판: android/app/src/byod (같은 소리 방식, 같은 듣는 화면, 같은 주소 길)

판 1.1.5 / 빌드 261010-BI1 / 2026-10-10 (이사장님 승인 "아이폰용도 진행", 방송클)
- 아이폰 첫 판. 안드로이드 BYOD 방송 1.1.5판(261009-B7)과 같은 기능을 아이폰에 옮김
- 첫 화면: 협회 로고 머리, BYOD 방송 시작 큰 단추 하나(방송 중에는 BYOD 방송 멈추기, 5초 안에 두 번 눌러야 멈춤), 바로 아래 현장 점검
- 새 판이 있을 때만 방송 단추 아래 한 줄(두드리면 테스트플라이트), 방송 중에는 업데이트 막음
- 상태 글: 바뀔 때만, 듣는 분 수만 바뀐 때는 10초에 한 번까지 보이스오버에 알림. 소리 받는 곳(실제로 들어오는 장치)과 할 일 한 줄
- 듣기 주소: 방송 중에만, 유선 랜(어댑터) → 와이파이 → 개인용 핫스팟 차례로 찾음, 바뀌면 바로 따라감
- 도움 요청: 듣는 분이 폰에서 누르면 첫 화면에 한 번 알림(같은 번호·같은 종류는 1분에 한 번)
- 소리 받기: AVAudioEngine 측정 방식(소리를 다듬지 않음), USB 사운드카드 → 이어폰 마이크 단자 → 라인 차례로 고름, 꽂고 빼면 저절로 다시 고름, 전화로 끊겼다 끝나면 다시 받음
- 16000Hz 한 줄 16비트를 0.1초씩 뮤로 줄여 보냄(노트북판·안드로이드판과 같음)
- 서버: 8080번 문, 길 이름은 안드로이드판과 같음(/ /status /stream /daegi.mp3 /ment.mp3 /yocheong 등), 인터넷 있는 척(아이폰·안드로이드·윈도우 확인 주소)
- 나눠 보내기: 보내는 일꾼 하나가 모든 폰에 기다리지 않고 보냄(듣는 분마다 일꾼을 두지 않아 300명 이상에도 일꾼 수가 늘지 않음). 폰마다 4초까지 쌓고 밀리면 오래된 소리를 버림, 10초 넘게 하나도 못 받은 폰은 끊고 빼고 셈
- 현장 점검: 방송, 사운드카드, 소리 받는 곳, 소리 크기, 공유기와 듣기 주소, 스티커 주소와 견주기, 배터리와 충전 — 맨 앞 판단 한 줄, 다시 점검·결과 복사
- 기기 점검(더 보기 안): 소리 받을 수 있는 장치, 지금 받는 장치, 내는 장치, 연결 주소, 결과 복사
- 접속 도구(더 보기 안): 엔에프시 스티커 쓰기(와이파이 붙기·듣기 주소 열기, 여러 장 이어 쓰기, 멈추기), 큐알 보기(와이파이 붙기·듣기 주소 열기), 큐알 그림 사진 앱에 저장. 아이폰은 지금 붙은 와이파이 이름을 알 수 없어 한 번 넣으면 기억
- 새로고침(더 보기 안): 나스에서 듣는 화면·대기 음악 받기 + 새 판 살피기를 한 곳에서
- 프로그램 말소리 켜기 끄기, 도움말 18가지(낱말로 찾기, 다섯 개씩 더 보기·이전 보기, 맨 위와 맨 아래 뒤로), 판 정보
- 보이스오버 두 손가락 문지르기로 뒤로, 첫 화면에서는 앱 밖으로 나가지 않음
- 앱 아이콘: 남색 바탕에 협회 로고(점자 lvd·LVD)와 노란 BYOD
- 설정: 뒤에서 소리(audio), 와이파이 늘 유지, 마이크·로컬 네트워크·엔에프시·사진 저장 허락 글, 엔에프시 TAG 권한
- 클 작업공간 점검: 스위프트 짓는 도구가 없어 짓지 못함. 따로 띄운 검토 일꾼이 모든 파일을 한 줄씩 읽어 짓기 오류는 없다고 보았고, 찾아낸 실행 문제 다섯 가지(보낸 소리가 메모리에 쌓임·껐다 곧바로 켤 때 옛 문 일꾼·소리 줄기 겹침·엔에프시 쓰기 겹침·듣기 주소가 바뀌어도 그대로 남던 것)를 고침. 깃허브 짓기에서 오류가 나면 방송클이 고침
